# 윙토언어 변환기 — 설계 스펙

- 날짜: 2026-08-14
- 경로: `D:\2026배경화면\myapp\wingto`
- 상태: 브레인스토밍 완료, 구현 계획(writing-plans) 대기

## 1. 개요

텍스트를 입력하면 한글 자모를 분해해서 "윙토언어"라는 커스텀 기호 체계로 변환해 캔버스에 보여주고, 결과를 PNG로 다운로드할 수 있는 무료 웹서비스.

**기술 스택**
- React + Vite (SPA)
- Tailwind CSS
- `xlsx` — 자모 매핑 엑셀 파싱
- `roughjs` — 캔버스에 손글씨(연필/크레용) 느낌으로 도형을 그리기 위한 렌더러 (신규 추가 결정)

**폴더 구조**
```
/src/components
/src/data          (symbolMap.js 자동 생성물)
/src/utils         (hangulDecompose.js, renderToCanvas.js, symbolShapes.js)
/scripts           (buildSymbols.js)
```
`/src/assets/symbols`는 사용하지 않음 — 아래 3.3 참고 (이미지 파일 대신 코드로 도형을 그림).

## 2. 배경 — 원 스펙에서 바뀐 두 가지

브레인스토밍 중 두 가지 중요한 변경이 있었고, 그 이유를 기록해둔다.

1. **엑셀 원본 파일 문제**: 사용자가 지정한 `(R)japil-form(Normal).xls`는 실제로는 손글씨 폰트 제작 신청서였고, "구분|자모|기호" 구조가 아니었다. 사용자가 표준 자모 목록을 직접 불러주어 그 데이터로 새 시작 파일을 만들기로 함 (3.1 참고).
2. **기호 저장 방식 변경**: 원 스펙은 "기호 = 이미지 파일명"을 전제로 했지만, 실제 사용자가 원하는 심볼 체계(아래 3.3)는 전부 기하학적으로 그릴 수 있는 도형 조합이라, 이미지 에셋 없이 코드(canvas 드로잉 함수)로 직접 그리는 방식으로 전환. Excel의 "기호" 칸에는 파일명 대신 **도형 키워드**를 적는다.

### 3.3 심볼 규칙 (핵심 — 반복 브레인스토밍으로 확정)

**표현 모델**: 초성은 "고유 도형", 중성(모음)은 초성 도형에 붙는 "작은 마크"(위치+선/점 개수로 구분), 종성은 초성과 같은 도형을 축소해서 배치. 쌍자음은 도형에 마커 추가.

#### 초성 14개

| 자모 | 도형 |
|---|---|
| ㄱ | 동그라미 |
| ㄴ | 하트 (봉우리 2개, 바닥은 완전히 뾰족하지 않고 양끝만 아주 살짝 둥글게) |
| ㄷ | ㄴ과 같은 구조, 봉우리 3개 |
| ㄹ | ㄴ과 같은 구조, 봉우리 4개 |
| ㅁ | 동그라미 안에 가로선 1개 |
| ㅂ | 동그라미 안에 가로선 2개 |
| ㅅ | 세모 |
| ㅈ | 세모 + 위 꼭짓점에 닿은 작은 빈 동그라미 1개 |
| ㅊ | 세모 + 꼭짓점에 닿은 빈 동그라미 2개(위아래로 쌓임) |
| ㅋ | 동그라미 + 꽃잎(작은 원) 1개 |
| ㅌ | 동그라미 + 꽃잎 2개 |
| ㅍ | 동그라미 + 꽃잎 3개 |
| ㅎ | 동그라미 + 꽃잎 4개 |
| ㅇ | 토성 모양 (원 + 수평 고리). **고리는 기울이지 않고 수평으로.** 고리 뒤쪽 절반은 원 뒤로, 앞쪽 절반은 원 앞으로 그려서 겹치는 부분이 한 줄로만 보이게 레이어링 |

꽃잎(ㅋㅌㅍㅎ) 배치 규칙: 꽃잎은 중심 원보다 크게, 여유 있게 띄워서(태양/꽃 느낌) 배치하되 중심 원과 살짝 겹치게 하고, **겹치는 부분은 중심 원을 나중에(위에) 그려서 꽃잎 선이 안 보이게 가린다.** 꽃잎 개수만 맞으면 정확한 배치는 유연하게.

#### 쌍자음 5개 (⚠️ 미확정 — 아래 5절 참고)

임시로 "기본 도형 + 정중앙에 작은 빈 동그라미"로 구현. 사용자가 제공한 참고 사진에는 더 복잡한 디자인(예: ㄸ은 하트 안에 작은 하트+점) 가능성이 있었으나 정확한 형태를 확정하지 못함. 구현 중 재확인 필요.

#### 중성 21개

기본 방향 마크 (자음 도형에 부착, 위치는 아래 표):

| 자모 | 마크 | 위치 |
|---|---|---|
| ㅏ | 짧은 선 1개 | 뒤(오른쪽) |
| ㅑ | 짧은 선 2개 | 뒤 |
| ㅓ | 짧은 선 1개 | 앞(왼쪽) |
| ㅕ | 짧은 선 2개 | 앞 |
| ㅗ | 짧은 선 1개 | 위 |
| ㅛ | 짧은 선 2개 | 위 |
| ㅜ | 짧은 선 1개 | 아래 |
| ㅠ | 짧은 선 2개 | 아래 |
| ㅣ | 검은 점 1개 | 뒤 |
| ㅡ | 검은 점 1개 | 아래 |
| ㅢ | 검은 점 2개 | 뒤 + 아래 |

이중모음 6개(ㅘㅙㅚㅝㅞㅟ)는 기본모음 마크의 조합으로 정의 (예: ㅘ=ㅗ+ㅏ, ㅟ=ㅜ+ㅣ). **ㅙ·ㅞ는 마지막 확인 라운드에서 "틀렸다"는 피드백을 받았고**, ㅗ/ㅜ 선 + ㅐ/ㅔ 전용 구조(아래)를 붙이는 방식으로 수정했으나 최종 확인 전 대화가 다른 주제로 넘어감 — **구현 전 재확인 필요**.

ㅐㅒㅔㅖ는 기본 마크가 아니라 전용 구조: 긴 세로선 + 작은 빈 동그라미(들).

| 자모 | 구조 |
|---|---|
| ㅐ | 세로선 중간에 빈 동그라미 1개 |
| ㅒ | 세로선에 빈 동그라미 2개, 틈 없이 붙여서 |
| ㅔ | 세로선 한쪽 끝에 빈 동그라미 1개 |
| ㅖ | 세로선 한쪽 끝(위)에 빈 동그라미 2개, 가로로 나란히 |

⚠️ 이 4개가 자음의 앞/뒤 중 어느 쪽에 붙는지는 사용자에게 직접 확인받지 못함 — 기본모음(ㅏ계열=뒤, ㅓ계열=앞)과 같은 쪽으로 임시 가정하고 진행함. **구현 전 재확인 권장.**

### 3.4 렌더링 스타일 — 손글씨 느낌 (rough.js)

색은 전혀 쓰지 않는다 (배경/버튼 등 UI 색상과 별개로, 심볼 자체는 순수 선화). 스트로크 색상은 진회색 `#4A4A4A`.

캔버스에 그릴 때 `roughjs`로 렌더링해서 연필/크레용으로 한 번에 쓱 그은 듯한 느낌을 낸다. 확정된 옵션값:

```js
{
  roughness: 0.35,
  bowing: 0.3,
  disableMultiStroke: true,       // 두 번 겹쳐 긋는 기본 스케치 효과 끄기
  disableMultiStrokeFill: true,
  preserveVertices: true,         // 도형 이음새가 끊겨 보이는 것 방지
  strokeWidth: 2.2,
  stroke: '#4A4A4A'
}
```

채우기(fill)는 기본적으로 없음. 단, **레이어링(겹침 뒤로 가리기) 목적**으로만 흰색(`fill:'white', fillStyle:'solid'`) 채우기를 예외적으로 사용한다 — 예: ㅇ의 원이 고리를 가릴 때, ㅋㅌㅍㅎ의 중심 원이 꽃잎을 가릴 때.

## 4. 한글 분해 로직 (`hangulDecompose.js`)

원 스펙 그대로:
- 완성형 한글 → 초성/중성/종성 유니코드 계산으로 분해
- 겹받침(ㄳㄵㄺㄻㄼㄽㄾㄿㅀㅄ)은 구성 자음 2개로 재분리 (예: ㄳ → ㄱ+ㅅ)
- 숫자(0-9), 물음표, 느낌표는 별도 기호로 매핑
- 그 외 비한글 문자(영어, 공백 등)는 원문 그대로 통과
- 순수 함수로 작성 (단위 테스트 가능)

## 5. 캔버스 렌더링 (`renderToCanvas.js` + `symbolShapes.js`)

**`symbolShapes.js`**: 도형별 rough.js 드로잉 함수 카탈로그. 3.3의 각 도형("동그라미", "하트류(봉우리 n개)", "원+가로선(n개)", "세모+빈원(n개)", "원+꽃잎(n개)", "토성", "U 반복(n)", "아치 반복(n)+원", "별", "소용돌이", "지그재그 4갈래" 등)을 매개변수화된 함수로 구현.

**합성 알고리즘**:
1. 음절을 초성/중성/종성으로 분해 (겹받침은 이미 분리된 상태)
2. 초성 도형을 음절 셀 중앙에 기준 크기로 그림
3. 중성 마크(들)를 초성 도형의 지정된 변(위/아래/앞/뒤)에 부착
4. 종성이 있으면 초성과 같은 도형을 축소해서 우하단에 배치 (겹받침이면 2개 나란히)
5. 다음 음절로 커서 이동, 캔버스 폭 초과 시 줄바꿈

자모 간 간격, 음절 간 간격은 변수로 조절 가능하게. 캔버스 크기는 텍스트 길이/줄 수에 따라 동적 계산.

## 11. 미확정 항목 (구현 중 재확인 필요)

1. **쌍자음 내부 마커**: 정중앙 빈 원으로 임시 처리. 사용자 사진상 더 정교한 디자인(하트+점 등) 가능성 — 재확인 필요.
2. **ㅐㅒㅔㅖ 부착 위치**: 앞/뒤 중 어느 쪽인지 명시적 확인 못 받음. 기본모음과 같은 쪽으로 가정.
3. **ㅙ·ㅞ 조합 방식**: "틀렸다" 피드백 후 수정했으나 최종 승인 전 대화 종료. 재확인 필요.
4. **소용돌이(?) rough.js 렌더링**: `curve()`보다 `path()` + 베지어 좌표가 더 안정적이었음. 최종 곡선 좌표는 렌더링 시 미세 조정 여지 있음.
